## Overview

CodeExperts Gists Viewer allows a reviewer or end user to:

- Enter any GitHub username in a browser UI and instantly retrieve a list of their public gists as clickable links.
- Consume the same data programmatically via a clean REST endpoint.

The backend calls the public [GitHub REST API](https://docs.github.com/en/rest/gists) asynchronously, validates the response with Pydantic, and returns structured JSON. All external HTTP errors are mapped to appropriate HTTP status codes before reaching the client.

## Architecture

```
Browser / API Client
        │
        ▼
  FastAPI (main.py)
  ├── GET /               → Serves index.html (HTML frontend)
  └── GET /gists/{user}   → Calls get_gituser_gist()
                                    │
                              gist.py (business logic)
                                    │
                           httpx.AsyncClient
                                    │
                        GitHub API  (api.github.com)
                                    │
                           Pydantic validation
                           (app/models.py)
                                    │
                              JSON response
```

## Local Setup (without Docker)

### 1. Extract and enter the project

```bash
unzip CodeExperts.zip
cd CodeExperts
```

### 2. Create a virtual environment

```bash
python3 -m venv myenv
```

Activate it:

```bash
# macOS / Linux
source myenv/bin/activate

# Windows (PowerShell)
myenv\Scripts\Activate.ps1

# Windows (Command Prompt)
myenv\Scripts\activate.bat
```

### 3. Install dependencies

```bash
pip install --upgrade pip
pip install -r requirements.txt
```

This installs:

| Package | Purpose |
|---|---|
| `fastapi` | Web framework and routing |
| `uvicorn[standard]` | ASGI server to run FastAPI |
| `httpx` | Async HTTP client for GitHub API calls |

## Running with Docker

The project uses a **multi-stage Docker build** — a builder stage installs dependencies and a slim runtime image runs the app under a non-root user for security.

### 1. Build the image

```bash
docker build -t codeexperts .
```

### 2. Run the container

```bash
docker run -p 8000:8000 codeexperts
```

### 3. Verify

```bash
curl http://localhost:8000/gists/torvalds
```

Or open [http://localhost:8000](http://localhost:8000) in your browser.

### Docker build summary

| Stage | Base Image | Purpose |
|---|---|---|
| `builder` | `python:3.13` | Installs all dependencies into `/install` |
| Runtime | `python:3.13-slim` | Copies only app + installed packages; runs as `appuser` |

The multi-stage approach keeps the final image lean and excludes build-time tooling. The app runs as a non-root user (`appuser`) to follow container security best practices.

## Running the Tests

The test suite is in `test_gists.py` and covers the `get_gituser_gist` function using a custom `MockClient` to simulate GitHub API responses — no real network calls are made.

### 1. Install test dependencies

```bash
pip install pytest pytest-asyncio
```

### 2. Run all tests

```bash
pytest test_gists.py -v
```

### Expected output

```
test_gists.py::test_get_gists_success    PASSED
test_gists.py::test_get_gists_empty      PASSED
test_gists.py::test_user_not_found       PASSED
test_gists.py::test_network_error        PASSED
test_gists.py::test_unexpected_error     PASSED

5 passed in 0.XXs
``` 

### Test coverage summary

| Test | Scenario covered |
|---|---|
| `test_get_gists_success` | GitHub returns a valid list of gists; validates ID, description, and URL fields |
| `test_get_gists_empty` | GitHub returns an empty array; function returns `[]` without error |
| `test_user_not_found` | GitHub returns 404; raises `RuntimeError` with `"GitHub API error"` in the message |
| `test_network_error` | `httpx.RequestError` is raised; propagates as `RuntimeError` with `"Network error"` |
| `test_unexpected_error` | Arbitrary `ValueError` is raised; function wraps it in a `RuntimeError` |

## API Reference

### `GET /`

Serves the HTML frontend.

**Response:** `200 OK` — `text/html`

---

### `GET /gists/{username}`

Fetches public gists for the given GitHub username.

**Path parameter:**

| Parameter | Type | Required | Description |
|---|---|---|---|
| `username` | `string` | Yes | A valid GitHub username |

**Success — `200 OK`:**

```json
[
  {
    "id": "abc123def456",
    "description": "My useful script",
    "url": "https://gist.github.com/username/abc123def456"
  }
]
```

**Response schema:**

| Field | Type | Nullable | Description |
|---|---|---|---|
| `id` | `string` | No | Unique gist identifier |
| `description` | `string` | Yes | Gist description — `null` if not set by the author |
| `url` | `string` | No | Direct link to the gist on GitHub |

**Empty result — `200 OK`:**

```json
[]
```

Returned when the user exists but has no public gists.

## Error Handling

All errors from the GitHub API or the network layer are caught in `gist.py` and mapped to structured HTTP responses before reaching the client.

| Scenario | HTTP Status | Example `detail` |
|---|---|---|
| GitHub user not found | `404 Not Found` | `"GitHub API error: 404"` |
| Any other GitHub API error | Mirrors GitHub's status | `"GitHub API error: 403"` |
| Network / connectivity failure | `503 Service Unavailable` | `"Network error: Connection refused"` |
| Unexpected internal exception | `500 Internal Server Error` | `"Unexpected error: ..."` |

**Error response body:**

```json
{
  "detail": "GitHub API error: 404"
}
```

## Known Limitations

- **GitHub rate limiting** — unauthenticated requests to the GitHub API are limited to **60 requests per hour** per IP address. To raise this limit, add an `Authorization: Bearer <token>` header to the `httpx` client in `gist.py` using a [GitHub personal access token](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/creating-a-personal-access-token).
- **Public gists only** — the `/users/{username}/gists` endpoint only returns public gists. Private gists require OAuth authentication scoped to the target user.
- **No pagination** — the GitHub API returns up to 30 gists per page by default. Users with many gists will receive a truncated list unless pagination (`?page=` / `?per_page=`) is implemented.
- **Pinned Python version** — the project targets Python 3.13 (see `.python-version`). Running on an earlier version may cause compatibility issues with type hints and library internals.
